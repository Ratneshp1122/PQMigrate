# Architectural Decision Record (ADR) 001
## Semantic Migration & Explicit Abstention Policy

**Status:** Accepted
**Date:** 2026-09-24

### 1. Context
Earlier prototypes of `PQMigrate` utilized a "Primitive Name → Target Algorithm" dictionary (e.g., replacing `RSA` with `ML-KEM`). This approach is architecturally unsound because cryptographic primitives are multi-role. RSA can be used for Key Encapsulation/Transport, Digital Signatures, or Protocol Identity. Replacing an RSA signature with ML-KEM (a Key Encapsulation Mechanism) fundamentally breaks the application. 

### 2. Decision
1. **Role Inference is Mandatory:** The tool shall not map a legacy primitive to a PQC primitive without establishing its cryptographic role (`signature`, `key_agreement`, etc.) through dataflow or call-site context.
2. **Abstention Policy:** If the tool detects a legacy primitive (e.g., `import rsa`) but cannot confidently infer its role, it must output an `inventory_lead` and **ABSTAIN** from generating a migration patch.
3. **No Direct Algorithm Replacement Guarantees:** Migration patches will focus on standardizing against hybrid schemes (e.g., RFC 10024) where available, rather than homegrown combiners.

### 3. Consequences
- **Positive:** Automated patches generated by the tool have mathematical and architectural safety guarantees.
- **Negative:** The tool will generate fewer automated patches, increasing the "manual intervention" count.
- **Academic Impact:** This strictly aligns the tool with the rigorous requirements of USENIX Security/ACNS, allowing us to evaluate the *limits* of automated migration.
